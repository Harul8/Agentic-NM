Nyaymalaw Agentic Architecture
Current runtime architecture as of 2026-04-09

==============================================================================
1. Overview
==============================================================================

Nyaymalaw is a local-first Indian legal AI system. The agentic architecture
replaces the old two-phase hardcoded loop (fact_collection → response_generation)
with an LLM-driven orchestrator that holds a full tool set and decides
dynamically what to do: intake, research, verification, or all at once.

The core shift:
  OLD: pipeline/chat.py   → hardcoded phase transitions
  NEW: agents/orchestrator.py → LLM tool-use loop, parallel execution

==============================================================================
3. The 5-Layer Stack
==============================================================================

  Layer 1 — User Interface  [Frontend/]
    React frontend → /agent/stream (agentic) or legacy /conversation/continue/stream
    Claude Desktop / VS Code → mcp_server.py (stdio or SSE)

  Layer 2 — Orchestrator Agent  [agents/orchestrator.py]
    LLM with 12 tools. Runs tool-use loop until final answer.
    Parallel execution: search_bare_acts + search_case_laws fire concurrently.
    Streams step/token/done events via SSE.

  Layer 3 — Specialist Agents  [agents/intake/, agents/document/, agents/forum/, agents/verification/]
    Intake Agent      : start_intake → continue_intake → draft_opinion
    Research Agent    : search_bare_acts, search_case_laws, lookup_section, lookup_case
    Document Agent    : extract_document_facts, cross_reference_document
    Forum Agent       : identify_forum, check_limitation
    Verification Agent: runs after draft_opinion (citation check, evidence gap, limitation)

  Layer 4 — Retrieval & Grounding  [retrieval/]
    FAISS semantic search + BM25 lexical search
    Reciprocal-rank fusion + cross-encoder reranking
    Grounding guard rejects drafts that cite unsupported law

  Layer 5 — Memory & State  [platform/]
    Session memory: agents/intake/session.py + SQLite (api_server.py)
    Workflow state: persisted in chat records (stage, facts, session_id)
    LLM client, token budgeting, warmup, feedback logging, few-shot examples

==============================================================================
4. Active API Endpoints
==============================================================================

  POST /agent/stream           ← PRIMARY agentic endpoint (new)
    Request:  { message, conversation, workflowState }
    Response: SSE stream → step | token | done events

  POST /submit_case/stream     ← Legacy (uses pipeline/chat.py)
  POST /conversation/continue/stream  ← Legacy (uses pipeline/chat.py)

  Tool server (MCP):
    python mcp_server.py               (stdio — Claude Desktop / VS Code)
    python mcp_server.py --transport sse --port 8010  (SSE — Cowork / HTTP)

==============================================================================
5. The 12 MCP Tools
==============================================================================

  Research:
    search_bare_acts(query, top_k)
    search_case_laws(query, jurisdiction, top_k)
    lookup_section(act_name, section_number)
    lookup_case(case_name, para_num)

  Intake:
    start_intake(first_message)
    continue_intake(session_id, client_message)
    get_intake_state(session_id)
    draft_opinion(session_id)

  Document:
    extract_document_facts(file_text, dispute_context)
    cross_reference_document(document_facts_json, intake_state)

  Forum:
    identify_forum(intake_state_json)
    check_limitation(dispute_type, key_dates)

==============================================================================
6. Conversation Principles (unchanged from v5.0)
==============================================================================

Nyaymalaw behaves like a calm senior advocate doing real intake:
  - Opens with empathy when the facts call for it
  - Identifies the issue in plain human language
  - Asks 2-3 closely related questions per cluster
  - Tracks urgency, prior actions, evidence posture, relief posture
  - Never cites law from memory — uses retrieval tools only
  - Final answer: short fact framing, grounded legal analysis, practical next steps
